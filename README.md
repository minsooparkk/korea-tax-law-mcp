# korea-tax-law MCP 서버

한국 세법 그래프 DB를 AI에 연결하는 공개 MCP(Model Context Protocol) 서버입니다.
단순 법 조문을 찾는 것을 넘어, 유권해석 본문, 예규판례 찾는 데 탁월한 DB입니다.

국세청 조세법령 목록의 **현행 90개** 법·령·칙(법률 31 · 시행령 32 · 시행규칙 27), 판례·조세심판원 결정례 15.3만건, 국세청·법제처·행정안전부 해석례 14.8만건, 108개국 조세조약 조문 3천개가 그래프로 연결되어 있고, 조문마다 **시행일과 개정 연혁**이 붙어 있습니다. 목록의 역사 법령 2개(자산재평가법시행령·시행규칙)는 현행 그래프에서 제외합니다. AI가 세법을 "기억"이 아니라 **현행 원문 조회**로 답하게 만듭니다.

위임·별표·문서 인용은 **활성·검증되고 원천 스냅샷이 맞는 관계만** 따릅니다. 키워드 검색 히트는 검증된 인용이 아니며, 인용은 적용 확정이 아닙니다.

국가법령정보센터에서 직접 API로 호출하는 것이 아니라, Graph DB로 세법 DB를 다시 설계하여 AI로 하여금 법률 추론의 효과성/효율성을 극대화할 수 있도록 한 DB입니다.
```
https://mcp.taxdoctorai.com/mcp
```

## 왜 필요한가

프론티어 모델이 급진적으로 발달했음에도 불구하고 LLM은 세법 질문에 자주 유권해석, 판례 등을 지어내서 답합니다. 또한, 일반 Web 검색을 통한 AI 답변은 학습 시점 이후 개정을 모르고, 세율·한도 숫자를 섞고, 폐지된 조문을 인용합니다. 이 서버를 연결하면 AI가 답하기 전에 **현행 시행 버전 조문 원문**을 직접 확인합니다.

## 도구

현재 버전 **v0.9.2** ([CHANGELOG](CHANGELOG.md))

`search_tax`는 로컬 tax-ai-agent의 `GraphSearcher.search_for_query`와 같은 코드를
사용합니다. 법률→시행령→시행규칙과 연결 문서를 탐색하고, 각 결과에 실제 노드·관계
경로, DB 원문, 적용 시점 및 미확정 상태를 반환합니다. 런타임은 Python 3.11+이며
`server.py`와 `src/` 공통 검색 코드 번들을 함께 실행합니다.

| 도구 | 용도 |
|---|---|
| `search_tax` | 로컬과 동일한 통합 탐색, 결과별 실제 경로·원문·적용 시점, `as_of` 별도 조문 버전 조회 |
| `get_evidence` | 검색된 자료의 원문 이어읽기, 원문 전문·요지·미수록 구분 |
| `list_laws` | 수록 현행 법령 목록 + 시행일 (국세·지방세 구분). 목록 역사 법령 제외 |
| `search_articles` | 조문 전문검색 (복합어 부분일치 폴백 포함). 현행·검증 CONTAINS만 |
| `get_article` | 조문 현행 원문 전체 + 시행일 + 검증된 위임·별표·인용 |
| `get_article_history` | 조문 개정 연혁 ("언제 바뀌었나"). 미검증 버전 표시 |
| `search_cases` | 판례·조세심판원 결정례·국세청 심사·이의·적부 결정례 키워드 검색 (검증된 인용 아님) |
| `search_interpretations` | 국세청·법제처·행정안전부 해석례 검색. 쟁점 문장·키워드·문서번호 모두 받음 (검증된 인용 아님) |
| `verify_citations` | 초안의 해석례·판례 문서번호와 '법령명 제N조'가 실제로 있는지 확인 (존재 확인, 내용 일치 아님) |
| `search_annexes` | 별표·서식 검색 (세율표·기준금액·분류표) |
| `get_annex` | 별표 본문 전체 + 원본 HWP·PDF 링크 |
| `list_upcoming` | 공포됐으나 시행 전인 개정 조문 |
| `list_treaties` | 조세조약 체결국 목록 / 국가별 협약·의정서 이력 |
| `search_treaties` | 조세조약 조문 전문검색 (제한세율·고정사업장 등) |
| `get_treaty_article` | 조세조약 조문 원문 (국문 + 영문) + 그 조문을 개정한 의정서 |

## 연결 방법

통합 검색 예시:

```json
{"search_intents":{"law":["소득세법 제97조의2"],"ruling":["배우자 증여 이월과세"]},"as_of":"2023-01-01","limit":10}
```

`search_tax`의 `next_offset`으로 다음 결과를 조회합니다. `original_text.continuation`은
긴 원문을 이어 읽는 `get_evidence` 호출 인자입니다. 검색 집합은 로컬 검색기의 수집
상한을 따르며 전체 DB 건수는 아닙니다. `as_of_lookup`은 현행 그래프와 별도로 조회한
당시 조문입니다. 인용 문서의 적용 버전이 미해소이면 현행 적용으로 단정하지 않습니다.

**Claude** (웹/데스크톱): 설정 → Connectors → Add custom connector → `https://mcp.taxdoctorai.com/mcp`

**Claude Code**:
```bash
claude mcp add --transport http korea-tax-law https://mcp.taxdoctorai.com/mcp
```

**Codex CLI** (`~/.codex/config.toml`):
```toml
[mcp_servers.korea-tax-law]
url = "https://mcp.taxdoctorai.com/mcp"
```

**Gemini CLI** (`~/.gemini/settings.json`):
```json
{"mcpServers": {"korea-tax-law": {"httpUrl": "https://mcp.taxdoctorai.com/mcp"}}}
```

**구형 SSE 전용 클라이언트**: `https://mcp.taxdoctorai.com/sse`
**stdio 전용 클라이언트**: `npx -y mcp-remote https://mcp.taxdoctorai.com/mcp`

## 수록 범위

범위의 정본은 국세청 조세법령 목록(주요세법 + 기타세법·관련법령)입니다. **현행 90**,
목록 역사 **2**(자산재평가법시행령·자산재평가법시행규칙)는 현행 그래프에서 제외합니다.
표의 날짜는 **수록된 버전의 시행일**입니다. `—`는 해당 하위법령이 없거나 아직 미수록이라는
뜻이고, 최신 목록은 언제나 `list_laws`가 정본입니다.

이 MCP는 같은 로컬 Neo4j를 읽기만 합니다. 데이터셋 동봉이나 별도 검색 API가 아닙니다.

### 검증 링크와 불확실성

`get_article`의 위임·별표·인용은 활성(`active`)·검증(`verified`)되고 원천 스냅샷이
일치하는 관계만 반환합니다. 소득세법 제20조의 검증된 위임은 시행령 제38조이며,
비활성 위임이 가리키던 다른 조문은 숨깁니다.

문서 인용은 **그 문서가 그 조문을 인용했다는 식별**이지, 그 조문이 그 사안에
적용됐다는 확정이 아닙니다. `temporal_resolution=unresolved` 이거나
`resolved_version_id`가 없으면 현행 조문으로 메우지 마세요.

2026-09-06 수리 범위: remaining 문서 293,581건 재검증 오류 0. 전체 문서
325,581건은 선행 Case 32,000을 포함합니다. 적용 보고서 `semantic_coverage=false`
(부분 해소 193,826 · 모호 27,728 · 해소 불가 22,148)는 실행 실패가 아니라
불확실 인용은 불확실로 남긴 결과입니다.

그래프 물리 규모(노드 379,473 · 관계 2,838,346)는 **물리 건수이며 의미 확정이
아닙니다.**

### 별표·서식

세율표·기준금액·분류표는 조문이 아니라 별표에 있는 경우가 많습니다. 조문만 읽으면
"별표에 따른다"에서 막히므로 별표 본문을 함께 싣습니다.
`get_article`이 검증된 `HAS_ANNEX`로 그 조문의 별표를 함께 표시합니다.

### 시행예정 개정 — 25개 버전 · 조문 123건

공포됐으나 아직 시행되지 않은 개정문입니다. 현행 조문과 **분리해서** 담습니다 —
섞으면 어느 쪽을 답한 것인지 알 수 없게 됩니다.
`get_article`은 그 조문에 시행예정 개정이 있으면 시행일과 함께 경고합니다.

| 조세조약 조문 본문 | 국세법령정보시스템 | `taxlaw.nts.go.kr` 조세조약 메뉴 |

갱신은 매일 아침 증분 수집(법령 개정·신규 판례·해석례)이며, 수록 범위는 `list_laws`·
`list_treaties`로 확인합니다. 미수록 법령은 [국가법령정보센터](https://law.go.kr) 참조.

**별표 본문은 별표 API가 아니라 법령 상세 XML에서 옵니다.**

별표 상세 엔드포인트(`target=licbyl`)는 JS 껍데기만 주고 본문을 주지 않습니다. 본문은
법령 상세 XML 안의 `<별표단위>`에 들어 있어서, 별표만 따로 받는 경로로는 내용이 비어
옵니다.

**조세조약 — 개정의정서가 본문에 반영돼 있지 않습니다. 대신 연결해 뒀습니다.**

조약은 메타데이터(국가법령정보센터)와 조문 본문(국세법령정보시스템)을 서로 다른 원천에서
받아 합칩니다. 국세법령정보시스템이 주는 조문 본문은 **협약 원문**이라 이후 개정의정서가
반영돼 있지 않습니다. 스위스 제10조(배당)는 1980년 협약 그대로 10%/15%인데, 2012년
의정서가 이를 5%(지분 10% 이상)/15%로 바꿨습니다.

다행히 그 개정의정서 본문 자체는 부속문서로 함께 들어옵니다. 그래서 수집 단계에서
부속문서 본문의 `협약 제N조` 참조를 뽑아 해당 조문에 잇습니다. 조문 번호 없이 세율만
알리는 최혜국대우 통보는 소득 유형(배당·이자·사용료)을 조문 제목에 맞춥니다.

이제 `get_treaty_article`이 조문 본문과 함께 그 조문을 고친 의정서를 **발췌까지 붙여**
돌려줍니다.

```
## ⚠ 이 조문을 개정한 부속문서 1건
위 본문은 국세법령정보시스템이 주는 협약 원문이라 아래 개정이 반영돼 있지 않다.
- 개정 의정서(2012.07.25.) (발효 2012.07.25)
  발췌: 협약 제10조(배당) 제2항 세항 가)를 삭제하고, 다음과 같이 대체한다.
        "가) … 자본의 최소 10퍼센트를 직접적으로 소유하는 경우에는 배당총액의 5퍼센트"
  전문: get_treaty_article(country="스위스", article_number="개정 의정서(2012.07.25.)")
```

`list_treaties(country)`는 그 나라의 부속문서 목록을, `get_treaty_article`은 부속문서
제목으로도 전문을 돌려줍니다.

**남은 한계**: 개정 성격 부속문서 40건 중 35건에서 조문 참조를 뽑았습니다. 나머지와, 애초에
국세법령정보시스템이 부속문서를 싣지 않은 조약은 연결이 없습니다. 그 경우 국가 단위 경고
(후속 협약·의정서 N건 존재)만 표시되니, 제한세율처럼 숫자가 결론을 좌우하는 쟁점은
law.go.kr 원문을 반드시 대조하세요.

## 직접 호스팅

`server.py`와 동봉된 `src/` 공통 검색 모듈을 함께 실행합니다. Python 3.11+ 표준
라이브러리만 사용하며 외부 런타임 의존성은 없습니다. `bundle-manifest.json`은
배포된 공통 소스의 해시를 기록합니다.

```bash
NEO4J_HTTP=http://127.0.0.1:7474 NEO4J_USER=neo4j NEO4J_PASSWORD=... PORT=8788 python3.11 server.py
```

단, 같은 스키마의 Neo4j 그래프 DB가 필요합니다 (Law/Article/Case/Interpretation/Treaty/TreatyArticle 노드, 풀텍스트 인덱스, 관계의 `active`/`verified`/원천 스냅샷). 데이터 수집 파이프라인과 DB 덤프는 이 리포에 포함되어 있지 않으므로, 일반 사용자는 호스팅 엔드포인트 사용을 권장합니다.

기본 방어 설정: 도구 호출 IP당 분당 30회(`RATE_PER_MIN`), 핸드셰이크(`initialize`·
`tools/list`) IP당 분당 20회(`HANDSHAKE_PER_MIN`), 동시 쿼리 4개, 쿼리 타임아웃 8초,
read-only.

도구는 한 번도 안 부르고 `initialize`+`tools/list`만 반복하는 디렉터리 스캐너가
붙으면, `server.py`의 `BLOCKED_NETS`에 해당 IP나 대역을 넣어 403으로 끊을 수 있습니다
(기본값은 빈 목록). 대상은 `logs/usage-*.jsonl`을 IP×메서드로 갈라 `tools/call`이
0건인 IP를 찾으면 됩니다.
